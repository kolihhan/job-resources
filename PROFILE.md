## Positioning

Early-career software engineer with applied-AI strength.

Primary role families, in priority order:

- Applied AI / AI Application Engineer
- LLM / RAG / Agent Engineer
- AI Backend / AI Software Engineer
- Agent evaluation / LLM evaluation / AI quality engineering
- Search / Retrieval / RAG engineering
- AI-native Product Engineer / Backend Engineer where LLM/Agent work is a real part of the job

Secondary only when unusually strong and still close to the same narrative:

- general backend/SWE at an AI-native or high-quality product team;
- application-oriented AI platform work where Agent/RAG/evaluation remains central.

Default deprioritize/skip for the current search:

- pure computer vision / robotics / image-model roles;
- traditional ML without meaningful LLM/application overlap;
- generic MLOps;
- model-serving / inference / GPU / distributed AI infrastructure;
- deep platform / middleware / distributed-systems ownership;
- mature FDE / solution-architecture / customer-deployment ownership;
- generic SWE that requires a separate interview-prep track and does not compound the Applied-AI direction.

Do not require an `AI Engineer` title, but the actual work should reinforce the same Applied AI / Agent / RAG / AI-backend career direction.

## First-job preference

The immediate goal is interviews and offers for a suitable **permanent full-time** engineering job, normally on-site or hybrid.

Prioritize:

- production engineering ownership;
- Python/backend/API/database work;
- Agent/RAG/retrieval/evaluation systems;
- deployment, reliability, testing and observability around AI applications;
- code review and strong engineering peers;
- mentorship and a credible engineering ladder;
- portable skills and employer/team reputation;
- applied-AI work with real engineering depth rather than prompt/demo-only work.

Applied AI is a differentiator, not a substitute for engineering quality.

For the current job search, **permanent full-time is a hard filter**. Fixed-term, temporary, contract, trainee-without-confirmed-permanent-employment, staffing/bodyshop and project-only employment should be skipped/closed rather than promoted.

Keep using the current resume and project evidence. Change them only for a concrete application need or repeated relevant employer feedback. Do not restart portfolio polishing as a substitute for applications.

## Malaysia TOP definition

Malaysia is an active parallel lane, but **TOP is role-level, not logo-level**.

Prefer roles with a strong combination of:

- credible engineering/product environment;
- meaningful Applied AI / Agent / RAG / AI backend depth;
- good compensation and reasonable WLB when evidence exists;
- mentorship, growth and career portability;
- strong fit with the candidate's actual evidence.

A famous bank, GLC, consultancy or MNC name alone does not make a role TOP. Generic operations, low-depth IT support, bodyshop/outsourcing, weak consulting implementation, generic traditional ML or non-AI fallback roles should not displace better opportunities.

## Opportunistic Web3 work

Web3 / crypto is not a primary discovery lane. Only consider it when the role is **permanent full-time**, credible, technically strong and clearly useful for the same backend/AI engineering career direction.

Do not create a separate contract/part-time/project lane in this repo while the permanent-only rule is active.

## Seniority

- Prefer new graduate / 0–3 years roles.
- A 2–4 year role may survive as a selective stretch only when the company, work and fit are unusually strong and the actual scope is still early-career realistic.
- Mandatory `3+ years` is a meaningful negative signal; deep-verify only when the wording clearly permits relevant project/research/part-time evidence or the role is otherwise exceptional.
- Skip hard 4+/5+ YOE, Senior / Staff / Lead / Manager, or roles whose actual scope clearly assumes mature enterprise/platform/customer ownership even when the numeric YOE gate is weak or absent.
- Specialized professional-experience floors matter: e.g. `2+ years professional AI application/service development` should not be satisfied by academic/project AI work plus unrelated software employment.

## Search markets

### Active target: Singapore

Search Singapore actively for early-career Applied AI / Agent / RAG / evaluation / AI backend / AI-native product roles.

- Unknown sponsorship/pass willingness is allowed at APPLY.
- Explicit no-sponsorship/right-to-work-only wording is a blocker.
- MCF-only application routes are blocked.
- Prefer employers/roles where compensation and hiring structure make EP/S Pass support realistic when evidence is available, but do not require public sponsorship wording before applying.
- Do not broaden into generic infra/platform/CV/ML roles merely because the company is strong.

### Active target: Mainland China

Search Mainland China actively, especially AI-native product companies, enterprise AI, developer tools, Agent/RAG, evaluation, AI backend and search/retrieval teams.

- Distinguish legal work-permit plausibility from employer willingness.
- Employer willingness may remain UNKNOWN until engagement; UNKNOWN alone must not prevent an otherwise strong, live, eligible role from reaching APPLY.
- Favor 2026-compatible, recent-graduate and 0–3 YOE opportunities.
- Strong 2–4 YOE stretches survive only when scope and fit are genuinely early-career realistic.
- Avoid expanding into pure algorithm research, CV, generic ML platform, inference/serving or deep distributed infrastructure unless the role is explicitly early-career and still close to the target lane.

### Paused: Hong Kong

Hong Kong is **paused as of 2026-10-23**.

- Do not discover new HK roles.
- Do not promote new HK APPLY/ACTION items until the user explicitly reactivates HK.
- Existing submitted `WAIT` items remain open only so employer replies are not lost.
- If an existing HK employer replies, process that lifecycle event normally.
- Roles closed only because HK was paused may be reconsidered later, but must be freshly revalidated after reactivation.

### Parallel lane: Malaysia TOP only

Malaysia runs in parallel because there is no foreign-work-permit friction, but do not fill the queue with ordinary fallback jobs.

Prefer Applied AI / AI Software Engineer / LLM / RAG / Agent / evaluation / AI backend roles at genuinely high-quality employers/teams.

Strong general SWE/backend may survive only when the employer/team is genuinely TOP and the role provides excellent engineering growth/portability without pulling the candidate into an unrelated direction.

Do not spend search time verifying Malaysian sponsorship. Normal role fit, liveness, company/team quality, dedupe and application-route checks still apply.

Employers with meaningful regional engineering exposure are a plus, but do not assume future internal transfer without evidence.
