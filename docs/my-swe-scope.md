# Malaysia SWE Scope

This file records the user's explicit 2026-10-28 scope expansion for the Malaysia market. Under the repository precedence rules, this explicit user-directed scope overrides older MY-ENG wording that required generic software roles to be materially AI-related. This override applies to **Malaysia only** unless the user later broadens Singapore or Mainland China as well.

## Goal

`../PROFILE.md` governs content-first priority. **Generic MY SWE/backend is DEPRIORITIZE fallback**, never above GOLD/ACCEPTABLE ADJACENT for permanent status, prestige, easy apply or local work rights. A SWE-title role whose actual LLM/NLP work satisfies GOLD or ACCEPTABLE ADJACENT is classified accordingly; title alone never downgrades it. This supplement preserves broader destination-quality SWE eligibility through bounded secondary discovery.

For Malaysia, retain bounded secondary discovery of **destination-quality permanent full-time software engineering roles** that the candidate would genuinely consider over continuing the Singapore / Mainland China search.

Do not turn Malaysia into generic volume. The existing MY TOP / destination-quality bar remains in force.

## Valid MY-ENG families

In addition to the existing Applied AI / ML / LLM / Agent targets, MY-ENG now includes:

- Software Engineer / Software Developer;
- Backend Engineer / Backend Software Engineer;
- Full-stack Engineer / Web Software Engineer;
- Platform Engineer / Cloud Software Engineer;
- Developer Platform / Infrastructure Software Engineer when realistic for the candidate;
- Data Engineer when the work is primarily software/data-platform engineering rather than BI/reporting;
- DevOps / SRE / Automation Engineer when the role is software-heavy, early-career realistic, and offers strong engineering portability;
- Test Automation / SDET only when it is genuinely engineering-heavy and destination-quality, not low-upside manual QA.

AI relevance is a bonus for these Malaysia roles, **not a mandatory gate**.

## Malaysia quality gate

A non-AI SWE role should enter APPLY/CHECK only when it is plausibly destination-quality, for example:

- strong MNC / global engineering hub;
- strong regional product-tech company;
- serious bank / digital bank technology organization;
- credible product company with strong software engineering peers, code review, architecture, cloud/platform exposure, and career portability.

Continue to reject:

- weak outsourcing / bodyshop roles;
- low-upside maintenance-only work;
- ordinary local generic SWE with weak technical environment;
- manual QA / support-heavy roles with little engineering ownership;
- for generic SWE, contract/fixed-term, trainee, internship, staffing or project-only employment; research employment remains governed by `RULES.md` section 5;
- mature senior roles or hard 4+/5+ professional-YOE floors without a truthful alternative route.

## Candidate-fit interpretation

The candidate is not only an AI applicant. Truthful Malaysia SWE positioning includes:

- multi-year paid part-time production software development;
- full-stack/backend ownership with Laravel / Vue / MySQL;
- deployments, Linux/server operations, SSL, queues/workers, scheduling, and production troubleshooting;
- Python / FastAPI / REST APIs / SQL;
- MSc CS plus applied AI work as an additional differentiator.

Do not inflate part-time/intern experience into fictitious conventional full-time YOE, but do not discard it either when an employer asks for generic software-development experience.

## MNC / strong-employer discovery emphasis

MY-ENG discovery should explicitly rotate strong software employers and engineering hubs, not only AI employers. Examples include Keysight, Intel, AMD, Dell, Lenovo, Experian, Bosch, Infineon, Motorola Solutions, Western Digital, Grab, Sea/Shopee, strong fintech/digital-bank engineering teams, and similarly strong current employers discovered through canonical first-party sources.

This list is a watch universe, not a whitelist.

## Regression examples

- A strong regular Experian Cyberjaya Software Engineer role may survive to full verification even when it is ordinary backend/full-stack/platform engineering.
- A weak local generic CRUD role should still fail the MY destination-quality gate.
