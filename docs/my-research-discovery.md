# Malaysia Research Discovery Supplement

This is a focused execution supplement for the existing `MY-RES` battlefield. `RULES.md` remains authoritative if anything here conflicts with it. GitHub Issues remain the only live opportunity state; this file is discovery guidance only, not a tracker.

## Goal

Increase recall of **destination-quality, MSc-compatible Malaysia AI research / applied-research roles** without weakening the permanent-employment, seniority, liveness, dedupe, or MY-TOP quality gates.

A research role may have a generic engineering/data title. Do not require the word `research` in the title when the actual work is materially research-oriented.

## Research query family

Rotate across these title / work families instead of relying on one broad `AI` query:

- `Applied Scientist`, `Applied AI Scientist`, `AI Scientist`;
- `Research Engineer`, `ML Research Engineer`, `AI Research Engineer`;
- `AI Researcher`, `ML Researcher`, `NLP Researcher`, `LLM Researcher`;
- `Research Scientist`, `Machine Learning Scientist`, `Generative AI Scientist`;
- `AI Safety Researcher`, `LLM Security Researcher`, `Adversarial ML`, `AI Red Team`;
- `NLP`, `LLM`, `retrieval`, `ranking`, `evaluation`, `post-training`, `fine-tuning`, `multimodal`, `agent`, `RAG` when the role contains real experimentation / model / evaluation ownership;
- research-heavy `Data Scientist` / `ML Engineer` roles when the JD includes hypothesis-driven experimentation, model research/prototyping, novel-method evaluation, publication/patent/research output, or close research-to-production transfer.

Cheap-screen false positives aggressively: generic analytics, BI/reporting, ordinary app development, shallow wrappers, non-AI security research, and mature senior roles do not survive merely because a description says `research`.

## Source strategy

Keep the existing first-party-first contract. Add a bounded **research recall layer**:

1. **Known / core employer official owners** — scan employer careers / ATS normally.
2. **ATS-universe radar for unknown employers** — use public ATS-board indexes only as discovery/gap radar, then resolve every survivor to the employer-controlled role page before promotion. Useful radar references include:
   - `mherzog4/job-boards` for broad Greenhouse / Lever / Ashby board coverage;
   - multi-ATS scraper implementations such as `sukhhdipsingh/ats-job-scraper` only as implementation / coverage references, not job authority.
3. **Native/direct fresh heads** — LinkedIn / Indeed / JobStreet / Hiredly may reveal unknown employers or research titles; re-anchor to first-party evidence whenever possible.
4. **AI-role curated radar** — curated GitHub/job-board feeds may supply gap signals, but never replace first-party liveness or exact-route verification.

Do not add another persistent job database or mirror an external feed into this repo.

## Per-run budget

For each hourly MY scout, preserve the existing destination-quality search and add **one bounded MY-RES recall pass**:

- rotate 2–4 query-family terms or one research-specific source head;
- prioritize roles observed/updated recently;
- stop deep work immediately on exact Issue-history duplicates;
- deep-verify only plausible MY-TOP survivors;
- use the normal RULES pipeline for employment type, seniority, work authorization, liveness, Gmail dedupe, exact route, and durable Issue readback.

This is recall expansion, not a quota. A run may correctly produce zero survivors.

## MY-RES quality interpretation

`MY-RES` should include serious applied-research environments, not only academic-style labs. Strong examples include teams where the candidate would:

- design or reproduce experiments;
- build evaluation / benchmark / red-team suites;
- prototype or adapt models and methods;
- investigate failure modes / attacks / model behaviour;
- translate research findings into production systems;
- work with technically credible research/engineering peers.

Publication requirements are evidence-sensitive: `nice to have` is not a blocker; a hard mature publication record remains a blocker under `RULES.md`.

For very early startups, a technically strong role may reach `CHECK` when liveness and fit are proven but **destination-quality technical-peer depth / company stability** is the one remaining material decision. Do not automatically promote a tiny startup to APPLY just because the work is interesting.

## Regression target

- official employer careers surface lists the role as hiring now and full-time;
- work includes LLM/agent attack research, prompt injection/jailbreak/data-exfiltration/tool-call abuse, evaluation suites/red-team harnesses, and research-to-production detector transfer;
- no hard numeric YOE floor is stated;
- publications are nice-to-have;

A MY-RES discovery pass using this supplement should be capable of surfacing this role (or deduping it once an Issue exists). This is a regression example, not a permanent watchlist exception.
